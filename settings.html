自动配图

只影响自动配图：手动生成照常，带 [[ ]] 画图指令的楼层也照常配图。
酒馆不记录回复是怎么结束的，所以看回复本身：<game>（「解析内容」里设的正文标签）、``` 代码块或状态栏开了头没写完，或者写满了「最大回复长度」、停在句子中间，算被截断；回复里是接口 / 反代的拦截提示（PROHIBITED_CONTENT、content_filter、Content Exists Risk、blockReason 等），或者没有正文、只有一小段「抱歉，我无法……」「内容违规 / 被过滤」之类的话，算被拦截。这样的楼层不自动配图，会弹提示；点「继续」把回复写完后会重新判断。手动生成照常。

一楼画几张、画谁

由解析 AI 自动判断：比如前半段是晚上、后半段跳到了第二天早上，就画两张（先晚上，再早上）；整段都是同一个时间、同一个地方就只画一张。几张图按时间顺序显示在这一楼，最后一张是这一楼结束时的样子。多一张就多一次出图时间。所有模型模式共用。
比如主角选了 {{user}}，这一楼却只写了别的人物：解析 AI 改画这一楼的主要人物（有角色预设的用预设的外貌和角色 LoRA，没有的按正文写外貌）；一个人都没有就只画场景。所有模型模式共用。

画图指令

例：她穿上了鞋子 [[red high-heeled shoes]]。发送时括号里的内容从正文里拿掉（正文 AI 看不到），只交给解析模型，优先级最高。消息下方会显示指令，点 ✕ 删除。
图片显示位置 · 大小 · 保留版本 · 聊天界面上的按钮
解析 AI 从这一楼的正文里选最适合配图的那一段（通常就是画面那一刻），图片连同工具栏插在那一段后面。消息里有 <game>……</game> 时只插在它里面，不会插进前后的状态栏、选项、代码页；「多张图」的每一张也各自插在它那一段里。没有位置的图放在正文最后一段后面；聊天里找不到正文（例如画在框架里）时照上面的「图片位置」显示。所有模型模式共用。
图片显示在聊天栏旁边的浮动面板里，聊天里只留一个配图条，点它就显示那一楼的图。
拖标题栏移动，拖右下角调整大小，⤢ 放大，▥ 重置到侧边；⌖「跟随阅读位置」开着时，滚动聊天会切到正在看的楼层的图。
打开后聊天里不再只是一个配图条，而是像「正文下方」一样显示图片和工具栏（开了「图片插在正文中间」就插在正文里）；工具栏上的 ▥ 把这一楼显示到侧边面板。所有模型模式共用。

聊天界面上的按钮

一键开关就是最上面的「启用」，聊天时不用打开设置就能开关配图。默认在输入框左边的魔杖 🪄 菜单里：点魔杖，再点「ComfyUI 配图：开 / 关」。也可以放在输入框左边当一个 🖼 按钮（一点就开关，但容易误触；带斜杠、变暗 = 关着）。关掉后不再生成新图（自动配图和各个生成按钮都不画），也不给正文 AI 加状态栏、画面分级的要求，正在进行的配图会取消；已有的图照常显示，可以翻看、删除。斜杠命令 /ctimg-enable on|off 也能开关（可以做成快速回复按钮）。
按钮在回复的 ✏️ 旁边（鼠标移到消息上时出现），点一下就重新解析这一楼并出图（还没有图的楼层就是生成），和 🔄「全部重新解析」一样，结果作为新版本保留旧图。关掉后这个按钮只在消息的「…」菜单里。
这一节所有模型模式共用（开了「每个用户人设使用独立档案」时每个人设各有一份）。图片和提示词只存在消息的扩展数据里，不写进正文，正文 AI 看不到。
模式与档案按画面自动切换模型 · 每个人设独立档案
打开后，正文 AI 每次回复会在末尾加一个看不见的标记（<!-- 画面:NSFW --> 或 <!-- 画面:SFW -->）。配图前读这一楼的标记，自动切到对应模式再画（各用该模式自己的设置）；没有标记的楼层用当前模式。手动「编辑提示词」出图时不自动切换。MOSS-Image 不参与自动切换。
打开后，每个用户人设有自己的一整套设置（每个模型模式各一套，「图片显示」这个人设的所有模式共用一份）：角色预设、LoRA、提示词、触发词、工作流、模型和采样等，切换人设时自动换过去，连同这个人设上次用的模型模式（用 Anima 的人设切过去就是 Anima 模式）；API 设置所有人设共用。新建的人设、或者某个人设没用过的模式，全部是默认设置。

编辑预设

发给写画图提示词的解析 AI 作参考：剧情里写到这个角色穿上某一套（或画图指令里写 [[换上校服]]），服装就照这套的提示词写，再按剧情补充穿着状态；剧情没写换装就不会换。不会直接放进提示词。提示词按当前模式写（Krea 2、MOSS-Image 写英文描述，Anima 写标签或英文描述）。
「默认」= 用「出图参数」里的模型和 LoRA；渲染配置在「出图参数」里新建。
这个角色的 LoRA、强度和触发词在「出图参数 → LoRA」里设置。
配图风格剧情 / 漫画（MOSS-Image）· 提示词生成方式 · 解析提示词
固定外貌 + AI 补充：角色预设的外貌原样放进提示词，AI 只写服装、动作、表情等。AI 写完整提示词：把外貌交给解析 AI，由它写出整段提示词。两种方式都会自动加上最上面的「触发词」、角色的 LoRA 触发词和画风前缀 / 后缀。
漫画模式由解析 AI 直接用 MOSS-Image 的 JSON 版面格式（summary + items，和 FKEY LoRA 说明里的示例一样）写整页分镜：分几格（不超过上面的格数，1 = 整页一个画面）、每一格的镜头和人物、对话框里的字（用正文里的原话，MOSS-Image 能直接画出中文）。位置写成整页的百分比，扩展换算成像素坐标（abs_centralized），最终提示词就是这个 JSON 版面。回复里没有版面时会按「重试次数」重新请求，不会改用自然语言提示词；JSON 有小错（没转义的引号、被截断）时尽量修好、用读得出来的部分。
人物外貌总是由 AI 写进每一格，上面的「提示词生成方式」对漫画不起作用；画几页由解析 AI 按这一楼的内容决定（不超过「每楼最多几页」，默认 3）：内容少就一页；发生了好几件事、换了地点或时间、对话很多，就按时间顺序分成几页，每页插在正文里它画的那一段旁边，和「多张图」一样（「多张图」本身的开关对漫画不起作用）。每多一页就多一次出图时间。漫画的输出比较长，「解析模型」的最大输出低于 4096 时，漫画请求自动用 4096。「画对白」= 把正文里的对白写进对话框，关掉 = 整页不画任何文字。
打开后，和主角同在这一幕的其他人也可以画进来（最多 3 人），他们的外貌、穿着、位置由解析 AI 按剧情描写，有角色预设的照预设的外貌写。主角的角色 LoRA 会作用于整张图，其他人可能长得像主角。
字段：outfit 服装 / action 动作 / expression 表情 / demeanor 神态 / scene 场景 / camera 镜头 / lighting 光线。写在这里的字段每张图都用这个内容，解析 AI 不再写它。
宽高填 0 = 用「出图参数」里的分辨率。
漫画模式默认也是 0。FKEY 漫画 LoRA 训练时最多的尺寸是 848×1200，想用就在这里填上。

剧情

打开后，每楼只读 <game>……</game> 之间的内容（标签名可以改，不用写尖括号；有好几段就全读），标签外面的代码页、选项、小剧场不会被当成剧情。没有这个标签的消息（例如你自己发的）照常读全文，但去掉 ``` 代码块。所有模型模式共用这一项。
「不算正文的标签」中间的内容不当作正文（逗号分隔，不用写尖括号；默认 advice）。比如有的预设在你发消息后，把你发的话以 <advice>……</advice> 加到上一楼正文的末尾：那是你给下一楼的输入，不是这一楼的剧情，解析 AI 看不到它，图片也不会插到它后面。开没开「只读取正文标签里的内容」都有效。所有模型模式共用。
适合游戏 / 旁白 / 模拟器类的卡（卡名不是一个角色）：打开后，发给解析 AI 的剧情里 AI 的消息不再标卡名，改标「正文」；「自动」选主角时不把卡名当候选，也不把卡名当成可能同框的角色。普通角色卡不要打开（解析 AI 需要知道谁在说话）。「画谁」选 {{char}} 时仍然用卡名。所有模型模式共用。

之前的配图

之前几层楼的解析结果和最终提示词交给解析模型，让人物保持连贯；0 = 不参考。这些记录不在正文里，正文 AI 读不到。

「触发的条目」按剧情关键词试扫描，和正文生成的规则一样，但不会影响正文的粘性 / 冷却计时。

反向提示词

加在上面的反向提示词后面。解析模型在同一次请求里多写一个 negative 字段：这张图不该出现、容易画错的东西（只有一个人时的多人标签、没穿戴的衣物配饰、还没发生的动作等）。和上面重复的、和正向提示词里一模一样的标签会自动去掉。Anima 和 MOSS-Image 模式默认打开；Krea 2 的内置工作流（CFG 1）不使用反向提示词，只对会用到反向提示词的自定义工作流有用。
反向提示词自动加上 letterboxed, pillarboxed, border, white border, black border。动漫模型偶尔会把画面画窄，两边或上下留出白边 / 黑边（像把一张 9:16 的图放在 2:3 的画布中间）。这几个 Danbooru 标签就是描述这种图的，放进反向提示词，画面就会铺满整张图。Anima 模式默认打开；要用 CFG 大于 1 才起作用（Turbo LoRA 的 CFG 1 不行）；正向提示词里写了同样的标签时不加。

其他

ComfyUI 会把普通括号当成加权并去掉，Danbooru 标签里的括号（如 artoria pendragon (fate)）就丢了；打开后自动转义，写明权重的 (smile:1.2) 不受影响。
组装模板（高级）
{{trigger}} = 本模式触发词 + 角色的 LoRA 触发词。Anima 模式每行之间用逗号连接（标签），按官方推荐的顺序拼：画质 / 安全分级 {{prefix}} {{rating}} → 人数 {{count}} → 角色 {{character}}（角色的 LoRA 触发词 / 角色名）→ 画师 {{artist}}（本模式触发词）→ 其他标签；自己改了模板，这个顺序也会自动排好。Krea 2、MOSS-Image 模式每行是一句话。变量：{{trigger}} {{prefix}} {{suffix}} {{appearance}}（固定）＋ {{outfit}} {{action}} {{expression}} {{demeanor}} {{scene}} {{camera}} {{lighting}} {{others}}（AI）。某一行的变量全为空时整行省略。画面里有其他人物时，「A solo image…」这一行会自动去掉；模板里没写 {{others}} 时自动加在镜头那一行前面。
正文状态栏让正文 AI 在回复末尾写可折叠的穿着 / 状态 / 心情
状态栏折叠显示在正文最下面，点开才看得到。它是正文的一部分，正文 AI 之后的回复也能看到它；解析模型会把它单独拿出来重点参考。不需要世界书或脚本，扩展会把说明自动加进发给正文 AI 的提示里。
插入深度：说明插在倒数第几条消息之前，0 = 最后，越靠后 AI 越听话。解析模型按折叠标题找状态栏，改了标题之前的楼层就认不出了。
发给正文 AI 的说明（高级） 变量：{{name}} 写谁 · {{label}} 折叠标题 · {{lines}} 要填的各行 · {{fields}} 项目名，以及酒馆宏。

LoRA

风格 LoRA 每张图都加；角色 LoRA 只在画这个角色时加，两个同时用。角色预设在「角色预设」一节新建。
放在提示词最前面。Anima 模式按官方顺序放在人数标签后面（角色、作品的位置）：同人角色可以在这里写 Danbooru 的角色名和作品名，例如 hatsune miku, vocaloid，有角色 LoRA 时连同它的触发词一起写。

更多 LoRA

可以叠加任意多个，按顺序接在角色 LoRA、风格 LoRA 后面。「用于」选某个角色预设 = 只在画这个角色时加，选「所有图」= 每张都加；取消勾选 = 暂时不用。自定义工作流也会自动接上。
添加 LoRA
ComfyUI 里常用的「加载 LoRA」(LoraLoader) 会同时改模型和文本编码器；关掉这一项 = 「LoRA 加载器（仅模型）」。在 ComfyUI 里用哪种节点，这里就选哪种，否则同样的设置出的图会不一样。Anima 模式默认打开；Krea 2 和 MOSS-Image 的内置工作流只支持仅模型（MOSS-Image 的 LoRA 训练时文本编码器是冻结的）。

会使用的 LoRA

分辨率

和 ComfyUI 的 Resolution Selector 节点一样：宽高 = 像素数 × 1024² 按宽高比分配，对齐到 16 的倍数（例：2:3、1 MP → 832×1248）。打开解析模型选择后，全身图会选竖图、横向场景会选横图，上面的宽高比是它拿不准时的默认值；配图风格自己设了分辨率时以配图风格为准。
会自动对齐到 16 的倍数。Krea 2 Turbo 适合约 1–2 MP。

采样

跳层引导 = 官方模板里的 SLG 开关：出图时反向（负向）分支跳过指定的层，OpenMOSS 官方推荐打开，细节更好；关掉更写实，但细节可能崩；它可能让动漫画风颜色过重。
跳过的层：层号从 0 数起，MOSS-Image 共 42 层（0–41）。官方推荐 22，24、26 也有帮助；可以写几个（22, 24, 26）或一段（22-26）。空着 = 22。
开始 / 结束：就是 ComfyUI 里这个节点的 start_percent 和 end_percent，默认 0.000 和 0.500（只在采样的前一半跳层）。0 = 采样开头，1 = 结尾，可以写到三位小数；「结束」要大于「开始」。
只对内置工作流（和带 %slg_layers% 占位符的自定义工作流）有效；出图参数预设会一起保存。

放大

画完后先用放大模型放大，再缩放到选的倍数（例：4x 模型选 2 倍 = 先放大 4 倍再缩回一半，比直接放大 2 倍更清晰）。模型文件放在 ComfyUI/models/upscale_models/。Anima 模式已经填好了 4x_IllustrationJaNai_V3detail_DAT2_28k_bf16.safetensors，打开开关就能用。出图会慢一些、图片文件更大；「编辑提示词后生成」里可以单独关掉这一次的放大。
（默认打开）每张图先显示画好的原图，等排队的图（几楼、多张图）全部画完，再一张张放大，放大好的图自动替换原图；原图下面会显示「先出原图，排队的图画完后再放大」，可以点「不放大了」。放大前的原图另存在 ComfyUI 的 output/comfy-portrait-base 文件夹里（第二步要从那里读取），可以随时清空。关掉 = 每张图画完立刻放大，下一张要等它放大完。

开启思考会更慢，也更占「最大输出」。最低、超高、最大不是每家都支持（例如 OpenAI 的 minimal / xhigh、Claude 的 max），不支持的接口会报错，换回低 / 中 / 高就行。「附加请求参数」里自己写的同名参数优先。下面那一行写的是按现在的设置实际会发送什么。

工具调用和附加参数

打开后，解析模型通过调用 submit_picture 工具交回结果：画面字段、整段提示词、漫画版面都作为工具的参数，不在正文里写 JSON 或提示词。适合 Gemini 这类擅长工具调用的模型。模型没调用工具、在正文里写了 JSON 时照常读取（🐞 里会注明）。「自动」由模型决定，大多数模型会调用；不调用时改成「必须调用」（Claude 新模型不支持「必须调用」，会报错）。「附加请求参数」里自己写的 tool_choice 优先。只对「独立 API」生效。

超时和重试

接口偶尔报错（如 Invalid API parameter、429、502）或没返回可用的 JSON 时自动重试；取消、超时、设置填错、输出被截断不重试。GLM 的温度一般要在 0–1 之间。

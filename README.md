# ComfyUI 角色配图 (Krea 2 / Anima) — SillyTavern 扩展

正文 AI 回复完之后，用一个**额外的模型**读剧情，判断角色（默认是 {{user}}）此刻的状态，写出服装、动作、表情、神态、场景，
再和你**预先写好的固定外貌**（发型、面部等）拼成提示词，交给 ComfyUI 的 **Krea 2 或 Anima 文生图 + LoRA** 工作流出图，图片贴回这一楼。

- **两种模型模式**：Krea 2（英文自然语言）和 Anima（动漫模型，Danbooru 标签），在设置面板最上方切换；两边的设置**完全分开保存**，只有 API 设置共用（见「模型模式」）；也可以让正文 AI 标记画面分级，NSFW 自动用 Anima、其余用 Krea 2（见「按画面自动切换模型」）
- **触发词**：每个模式可以填自己的触发词，每张图都会带上（AI 写完整提示词时也会要求它写上，漏了自动补）
- 每张图有一个**主角**：{{user}}、当前角色、指定 NPC，或者让解析模型自动挑本楼的主角；默认的「剧情状态」会让一起出场的人也入镜，其他预设默认只画主角（配图风格里的「允许画面里出现其他人物」）
- **配图风格（解析预设）**：剧情状态 / 立绘模式（固定姿势，只换服装表情）/ 小说插画模式，可以复制修改成自己的
- **两种提示词生成方式**：固定外貌 + AI 补充，或者把人设交给 AI 让它写完整提示词
- **画图指令**：在消息里写 `[[...]]` 或 `【【...】】`，括号里的内容只给配图解析模型，正文 AI 看不到
- **正文状态栏**：让写正文的 AI 在每次回复末尾写一个可折叠的状态栏（穿着、动作、状态、心情），正文 AI 和解析模型都能看到，解析模型重点参考它
- 解析模型可以参考**之前几次配图的输出**（解析结果 + 最终提示词），也可以选择读取**当前世界书**
- **每个用户人设一个档案**：切换酒馆的用户人设时，角色预设、LoRA、提示词、模型模式等整套设置自动换成那个人设的
- 图片可以放在正文**上方 / 下方**，或者聊天栏两侧空白处的**可移动、可放大的浮动面板**里（电脑版；手机上自动改回上方或下方）
- **固定部分 + AI 部分**：发型 / 面部 / 体型 / 角色 LoRA 写死在角色预设里，AI 只负责会变化的部分
- **正文 AI 看不到**：图片和提示词存在消息的扩展数据里、单独渲染，不写进正文，不会进上下文，也不会作为图片发给多模态模型
- **自定义分辨率**、全局 LoRA + 角色 LoRA（留空自动旁路）
- **调试模式**：每层楼都能查看提示词、解析模型的输入输出、最终提交给 ComfyUI 的工作流

## 安装

1. 酒馆 → 扩展 → 安装扩展，填入本仓库地址：`https://github.com/sy-ciel/004`
2. 在 SillyTavern 1.19.0（release 分支）上测试通过；用到了 `SillyTavern.getContext()` 里的 `ChatCompletionService`、`ConnectionManagerRequestService`，太旧的版本可能缺这些接口
3. 设置面板在 扩展 → **ComfyUI 角色配图**（标题后面显示当前模式：(Krea 2) 或 (Anima)）

## ComfyUI 准备（Krea 2）

需要 ComfyUI **v0.26 或更新**（原生支持 Krea 2，不需要自定义节点）。模型从 [Comfy-Org/Krea-2](https://huggingface.co/Comfy-Org/Krea-2) 下载：

| 文件 | 放到 |
|---|---|
| `krea2_turbo_fp8_scaled.safetensors` | `ComfyUI/models/diffusion_models/` |
| `qwen3vl_4b_fp8_scaled.safetensors` | `ComfyUI/models/text_encoders/` |
| `qwen_image_vae.safetensors` | `ComfyUI/models/vae/` |
| 你的 LoRA | `ComfyUI/models/loras/` |

内置工作流（`workflows/krea2_turbo_t2i_lora_api.json`）和官方模板一致：

```
UNETLoader ─► 角色 LoRA ─► 全局 LoRA ─► KSampler (8 步 · CFG 1 · euler · simple) ─► VAEDecode ─► SaveImage
CLIPLoader (type = krea2) ─► CLIPTextEncode ─► ConditioningZeroOut (负向)
EmptyLatentImage (自定义宽高)
```

`workflows/krea2_turbo_t2i_lora_ui.json` 是同一个工作流的 UI 版，可以直接拖进 ComfyUI 检查模型是否齐全、手动试跑
（设置面板里也有下载链接）。

## 模型模式：Krea 2 / Anima

设置面板**最上方**是「模型模式」开关：Krea 2 | Anima。点一下就切换，正在生成的配图会被取消（不会出现用一个模式解析、另一个模式出图的情况）。

**两个模式的设置完全分开保存**，切换时整套一起换：角色预设（外貌、角色 LoRA）、渲染配置、配图风格（解析预设）、
提示词组装（前缀、后缀、反向提示词、模板）、触发词、工作流（内置 / 自定义 / 渲染配置里的专用工作流）、模型和采样、分辨率、
自动配图规则、图片显示位置、正文状态栏、解析内容（读几楼、世界书……）、调试模式等。第一次切到 Anima 时，Anima 这边是全新的默认设置。

**两边共用的只有 API 设置**：

- 「解析模型」一组：来源、API 地址、Key、模型、连接配置、附加请求参数、温度、最大输出、超时、重试次数
- 「ComfyUI 连接」里的地址、连接方式、浏览器直连地址，以及已读取的模型列表
- 最上面的「启用」和「按画面自动切换模型」

聊天记录里的配图也按模式区分：每一楼记得自己是哪个模式画的（🐞 调试里的「模型模式」）。

- 解析模型参考「之前的配图输出」「上一次状态」时，只看**同一模式**画的楼层（Krea 2 写的句子不会混进 Anima 的标签里，反过来也一样）
- 在 Anima 模式下对 Krea 2 画的楼层点 🎲：提示词是给另一个模型写的，所以会**按 Anima 重新解析**再出图（一定出图，不会被判断为跳过），之前在 Krea 2 里用 ✏️ 选的尺寸、LoRA 开关也不带过来；旧图保留为一个版本
- 这样的重新解析失败了（或 🖼 重新解析时被判断为跳过），这一楼仍然是 Krea 2 的：切回 Krea 2 还能照原样 🎲
- ✏️ 编辑另一个模式画的图时，窗口里会提示，出图用当前模式的模型、工作流、同名角色预设和反向提示词；这一楼从此算当前模式的，之前那个模式的解析结果不会交给当前模式的解析模型
- 角色预设导出的文件会记下模式；把 Krea 2 的预设导入 Anima 时会先确认（LoRA、渲染配置可能不适用）。v1.14 之前导出的文件都算 Krea 2 的
- 「全部恢复默认值」只恢复当前模式，另一个模式可以勾选一起恢复；勾着「保留 API 设置」时，两边共用的设置（包括温度、最大输出、超时、重试和「启用」）都不变
- 斜杠命令：`/ctimg-model anima`、`/ctimg-model krea2`，不带参数返回当前模式

### 按画面自动切换模型（NSFW 用 Anima，其余用 Krea 2）

模式开关下面的「按画面自动切换模型」（默认关闭）。打开后：

- 正文 AI 会收到一条要求，每次回复在**最后一行**写一个 HTML 注释：`<!-- 画面:NSFW -->`（含露骨的性内容或裸露）或 `<!-- 画面:SFW -->`。注释在聊天里看不见，也不会交给解析模型
- 每一楼配图前读这一楼的标记：NSFW 自动切到 **Anima** 模式，SFW 切到 **Krea 2** 模式，再按该模式自己的设置（角色预设、LoRA、提示词、工作流……）解析和出图。切换时会弹一个提示，🐞 调试里记下「画面分级：NSFW（正文 AI 标记）→ Anima 模式」
- 没有标记的楼层（关之前写的、AI 漏写的）用当前模式
- 🎲 / 🖼 也按标记切换；✏️ 编辑后生成不切换（提示词是在当前模式里写的）
- 这一项两个模式、所有人设共用；关掉后正文 AI 不再收到这条要求，模式只按手动开关
- 标记的格式也认 `<!--画面：NSFW-->`、`<!-- rating:SFW -->` 等写法；一楼有多个标记时以最后一个为准

### 每个用户人设一个档案

模式开关下面的「每个用户人设使用独立档案」（默认打开）：每个酒馆用户人设有自己的一整套配图设置，两个模型模式各一套，
包括角色预设、LoRA（风格 / 角色 / 更多 LoRA）、提示词、触发词、工作流、模型和采样等。切换用户人设时自动换成那个人设的档案，不用再手动调整；
API 设置（解析模型、ComfyUI 地址）所有人设共用。

- 每个人设记住自己上次用的模型模式：人设 1 用 Krea 2、人设 2 用 Anima，切到人设 1 马上就是 Krea 2 模式，切到人设 2 就是 Anima 模式
- 新建的人设（之前没切到过）全部是默认设置：默认模式（Krea 2）、默认提示词、空的触发词、默认角色预设；某个人设没用过的模式也是那个模式的默认设置
- 升级前的设置（两个模式）会成为当前人设的档案
- 锁定了人设的聊天，打开时人设变了，档案也跟着换
- 关掉这一项 = 所有人设共用一套设置

### 触发词

模式开关下面的「触发词」：逗号分隔，**这个模式的每张图都会带上**，放在提示词最前面（例如风格 LoRA 的触发词、Anima 的 `@画师名`）。

- 「固定外貌 + AI 补充」：由扩展加在提示词最前面（模板里的 `{{trigger}}` = 本模式触发词 + 角色的 LoRA 触发词）
- 「AI 写完整提示词」：要求解析 AI 每次把触发词原样写在 prompt 最前面；AI 漏写了，扩展自动补上；AI 已经写了就不重复
- 用自己的组装模板、模板里没有 `{{trigger}}` 时也会补在最前面；🔄 重新出图时如果改过触发词，也会补上新的
- ✏️ 编辑后生成是例外：提示词按你填的原样发送（方便和 ComfyUI 对比）

## ComfyUI 准备（Anima）

[Anima](https://huggingface.co/circlestone-labs/Anima)（CircleStone Labs / Comfy Org）是 2B 参数的**动漫 / 插画**模型，不擅长写实。需要 ComfyUI **0.16 或更新**。
模型从 `circlestone-labs/Anima` 下载：

| 文件 | 放到 |
|---|---|
| `anima-base-v1.0.safetensors` | `ComfyUI/models/diffusion_models/` |
| `qwen_3_06b_base.safetensors` | `ComfyUI/models/text_encoders/` |
| `qwen_image_vae.safetensors`（和 Krea 2 用的是同一个） | `ComfyUI/models/vae/` |
| `anima-turbo-lora-v0.2.safetensors`（可选，`circlestone-labs/Anima-Official-LoRAs`） | `ComfyUI/models/loras/` |

内置 Anima 工作流（`workflows/anima_base_t2i_lora_api.json`）和 ComfyUI 官方模板「Anima Base v1: Text to Image」一致，多了两个 LoRA 槽位：

```
UNETLoader ─► 角色 LoRA ─► 全局 LoRA ─► KSampler (30 步 · CFG 4 · euler · simple) ─► VAEDecode ─► SaveImage
CLIPLoader (qwen_3_06b_base, type = stable_diffusion) ─► CLIPTextEncode 正向 / CLIPTextEncode 反向
EmptyLatentImage (约 1 MP)
```

Anima 模式的默认值：

- **分辨率**约 1 MP（默认竖图 832×1248，分辨率下拉里是官方的 1 MP 尺寸）；太大容易重复人物、多出肢体
- **反向提示词**是真的会用的（CFG 4）：默认 `worst quality, low quality, score_1, score_2, score_3, blurry, jpeg artifacts, sepia`（官方模板的那一段）
- **提示词写法**（Anima 模式下，模式开关正下方的 **Danbooru 标签 | 英文自然语言** 开关）：默认用 Danbooru 标签；切到「英文自然语言」后，
  解析模型用英文句子写服装、动作、表情、场景（以及「AI 写完整提示词」的整段 prompt），提示词按句子拼接，默认模板也换成句子版；
  画质前缀、触发词照常加在最前面，AI 补充的反向提示词仍是标签。内置和自己的配图风格都适用（会在解析提示词末尾追加一条写法说明），每个人设档案各自保存
- **解析模型补充反向提示词**（默认打开，「提示词组装」里可以关）：解析模型在同一次请求里多写一个 negative 字段，列出这张图不该出现、容易画错的东西（只有一个人时的多人标签、没穿戴的衣物配饰、还没发生的动作等），加在全局反向提示词和角色的额外反向提示词后面；重复的、和正向提示词冲突的标签自动去掉。🐞 里能看到 AI 写的那部分
- **画风前缀** `masterpiece, best quality, score_7`；**组装模板**按标签写，每行之间用逗号连接（见「提示词是怎么拼的」）
- 解析模型被要求用 **Danbooru 风格的英文标签**写服装、动作、表情等（小写、空格代替下划线、逗号分隔），配图风格（剧情 / 立绘 / 小说插画）都有 Anima 版
- **括号转义**默认打开：`artoria pendragon (fate)` 会变成 `artoria pendragon \(fate\)`，否则 ComfyUI 会把括号当成加权并去掉；写明权重的 `(smile:1.2)`、`(artoria pendragon (fate):1.2)`（只转义里面那对）、`((smile:1.2))` 不受影响。`:d`、`:3`、`love live!` 这类标签原样保留（「提示词组装」里可以关）
- 没有 ComfyUI 端提示词扩写（官方 Anima 模板没有这一步，Krea 2 才有）
- 「出图参数」里：「恢复为官方 Anima 模板的设置」= 官方默认值；「改用官方 Turbo LoRA」= 官方模板打开 turbo_mode 时的设置（风格 LoRA 换成 `anima-turbo-lora-v0.2` 强度 1、8 步、CFG 1，快很多；CFG 1 时反向提示词基本不起作用）

## 快速上手

设置面板最上面是**模型模式**开关（Krea 2 | Anima）和这个模式的**触发词**，下面是常用开关：启用、AI 回复后自动配图、调试模式、画谁（主角），以及「为最新楼层生成」「查看各楼层提示词」。
其余设置按用途分组折叠，点分组标题展开；右上角可以「全部展开 / 全部收起」，展开过的分组下次打开还是展开的。

1. **ComfyUI 连接**（设置面板最下面的 API 设置里）：填地址（默认 `http://127.0.0.1:8188`），点「测试连接」。连接方式默认「酒馆后端代理」，不需要给 ComfyUI 开 CORS
2. **解析模型**（同样在最下面的 API 设置里，三选一）
   - 独立 API：任意 OpenAI 兼容接口（DeepSeek、智谱 GLM、OpenRouter、本地 LM Studio / Ollama 的 `/v1`……），填地址、Key，点「获取模型」后在下拉框里选模型。请求经酒馆后端转发。
     「附加请求参数」里的 JSON 会合并进请求体，例如 GLM 关闭思考：`{"thinking": {"type": "disabled"}}`
   - 酒馆连接配置：在酒馆的 Connection Manager 里建一个配置，这里选它
   - 酒馆当前 API：和正文共用
   - 填完点「测试解析模型」
3. **角色预设**：默认有一个 `{{user}}` 预设，把「固定外貌」改成你的角色（英文）。
   所有 LoRA 相关的设置都在「出图参数 → LoRA」里：风格 LoRA（每张图都加）和强度；选一个角色预设，设置它的角色 LoRA、强度和 LoRA 触发词。
   「更多 LoRA」可以叠加任意多个 LoRA（每张图都加，或只在画某个角色时加）。「出图参数」最下面的「会使用的 LoRA」列出画当前角色时实际会用的每个 LoRA 和强度。
   「LoRA 同时作用于文本编码器」= ComfyUI 的「加载 LoRA」节点（模型和 CLIP 用同一强度）；关掉 = 「LoRA 加载器（仅模型）」。和 ComfyUI 对比出图时，两边要用同一种节点。Anima 模式默认打开
   要画 NPC 就新建预设，名字填 NPC 的名字，别名里写剧情中的其它称呼。
   有多个用户人设时，每个人设自动有自己的一套设置（见「每个用户人设一个档案」），切到哪个人设就改哪个人设的
4. 最上面的**画谁（主角）**选 {{user}} / {{char}} / 自动 / 某个预设
5. 在「出图参数」里点「从 ComfyUI 读取列表」，然后在下拉框里选扩散模型、文本编码器、VAE、LoRA（列表里没有的可以选「✏️ 手动输入…」）
6. 正常聊天。AI 回复结束后会显示「正在解析角色状态… → ComfyUI 生成中…」，完成后图片出现在这一楼正文下方

自动配图只针对**刚生成完的最新一楼**；开场白（前面没有任何用户消息的楼层）默认不自动配图，可在「自动配图规则」里打开「开场白也自动配图」。
已经有结果（图片、失败或跳过）的楼层不会被自动重复生成，需要时点 🔄 或消息菜单里的 🖼。

「自动配图规则」里的「正文少于几 token 不配图」：AI 回复的 token 数（按酒馆当前分词器，和消息上显示的数字一样）少于这个值时不自动配图，0 = 不限制。
适合跳过「嗯。」、OOC 回复这类很短的楼层。只影响自动配图，手动 🖼 / 🔄 / `/ctimg` 照常；带画图指令的楼层照常配图；
短回复点「继续」写长后会重新判断，够长就会配图。中文 1 个字大约 0.6～1.5 token（看分词器），不好估的话在酒馆「用户设置」里打开「显示消息 Token 数」，看看平时的回复有多少再定。

## 配图风格（解析预设）与提示词生成方式

设置 →「配图风格」。解析预设决定发给解析 AI 的要求：

| 内置预设 | 效果 |
|---|---|
| 剧情状态（默认） | 解析 AI 只写这几项：角色、心情、衣服、和谁在做什么、什么动作、大概的环境，每项有长度上限，不繁琐。环境只写时代 / 风格 + 地点类型（中世纪酒馆、现代卧室），不写楼层、门牌号、地名。默认允许一起出场的人入镜。完整提示词见 [prompts/default-story-prompt.md](prompts/default-story-prompt.md) |
| 立绘模式 | 姿势、镜头、背景、光线固定（写在「固定内容」里），只随剧情换服装、表情、神态；适合竖图 |
| 小说插画模式 | 挑当前楼层最有画面感的瞬间，电影感构图、有氛围的光线、更丰富的环境；适合横图 |

每个预设可以改：

- **固定内容**：每行 `字段: 内容`（字段写英文或中文：outfit 服装 / action 动作 / expression 表情 / demeanor 神态 / scene 场景 / camera 镜头 / lighting 光线），这些字段每张图都一样。例如立绘的 `action: standing upright and facing the viewer`
- **允许画面里出现其他人物**：「剧情状态（默认）」默认打开，立绘和小说插画默认关闭（只画主角）。见下方「画面里的其他人物」
- **风格前缀**：加在全局「画风 / 质量前缀」后面
- **分辨率**：填了就覆盖全局分辨率（0 = 用全局），立绘竖图、插画横图可以分开设
- **解析提示词（高级）**：System 提示词和 User 模板
- 内置预设改坏了可以「恢复默认」；「复制」出来的是自定义预设，可以删除
- v1.24 / v1.25 改写了「剧情状态（默认）」的 System 提示词：没改过的会自动换成新版（同时打开「允许画面里出现其他人物」）；自己改过的保持不变，想用新版就点「恢复默认」（改动会丢失，可以先「复制」一份）

**提示词生成方式**（对所有预设生效）：

- **固定外貌 + AI 补充**（默认）：角色预设里的外貌原样放进提示词，AI 只写服装、动作、表情等，再按「组装模板」拼起来。固定内容直接覆盖 AI 写的对应字段，所以立绘的姿势一定不会变
- **AI 写完整提示词**：把角色预设的外貌（人设）交给解析 AI，要求它完整写进去，由它输出整段提示词。最终提示词 = LoRA 触发词 + 画风前缀 + 预设前缀 + AI 写的提示词 + 后缀。AI 没给出提示词时会自动退回第一种方式拼接

System 提示词里的 `{{output_rules}}` 会按生成方式换成外貌规则和 JSON 输出格式，所以同一个预设两种方式都能用。

### 画面里的其他人物

默认每张图只画主角一个人。想让同一幕里的其他人也入镜（比如小说插画里两个人对坐吃饭），
在「配图风格」里选中预设（例如小说插画模式），勾选「允许画面里出现其他人物」：

- 主角仍是画面中心，服装 / 动作 / 表情只写主角；画面时刻和主角在同一个场景、参与这一幕的其他人，解析 AI 会写进 `others` 字段（最多 3 人），包括外貌、穿着、位置和动作
- 解析 AI 会拿到 {{user}}、当前角色，以及最近两层里提到名字的角色预设的固定外貌，画进来时照着写，长相更稳定
- 「固定外貌 + AI 补充」时，提示词里会去掉「A solo image…」那一行，在镜头那一行前面加上 `Also in the scene: ...`；「AI 写完整提示词」时由 AI 把所有人写进整段提示词
- 没有其他人同框时仍然是单人图
- 注意：主角的角色 LoRA 作用于整张图，其他人可能被画得像主角；多人构图也比单人更容易出错，建议配合横图分辨率
- 这个选项是每个配图风格各自的设置，立绘、剧情状态等预设默认都不开
旧版本里改过的解析提示词，升级后会变成一个叫「我的解析提示词（从旧版本迁移）」的预设并自动选中。

### 先分析时间线，再写画面

剧情里常有「我先去换件衣服，然后一起去吃饭」这种还没做完的事。如果直接让解析 AI 写服装和动作，它容易画成已经换好衣服、正在吃饭。
所以解析 AI 现在要先在 JSON 里写三个分析字段（中文），再写服装、动作等画面字段：

| 字段 | 内容 |
|---|---|
| now_doing 此刻在做 | 画面这一刻实际在做什么，只算已经发生或正在进行的事 |
| now_wearing 此刻穿着 | 这一刻身上实际穿的衣服，还没换就写原来的衣服 |
| pending 还没做的事 | 正文里提到、但还没做或没做完的事（准备、打算、即将要做的） |

规则是：「准备 / 打算 / 要去 / 正要 / 待会……」只算计划，正文没写到做完就按没发生处理；
换装要正文写到换好了才算；画面字段必须和 now_doing、now_wearing 一致，pending 里的事不画。
下一楼解析时，上一张图的这三项会出现在「之前的配图输出」里，正文写到做完了才会更新。
`[[ ]]` 画图指令优先级最高，不受这条限制。

- 这三项只用来分析和检查，**不会进提示词**，也和其它配图数据一样不会发给正文 AI
- 在 🐞 弹窗「② AI 解析部分」的「时间线分析」里可以看到，方便检查解析 AI 的判断
- 规则在 `{{output_rules}}` 里，三个内置预设和从它们复制出来的预设都自动生效；
  如果你的自定义 System 提示词删掉了 `{{output_rules}}`，需要自己加上类似要求

## 多张图（正文换了时间或地点时，每一段各画一张）

设置面板上方的「**多张图：正文换了时间或地点时，每一段各画一张**」（默认关闭），旁边选「最多 2 / 3 / 4 张」。打开后由解析 AI 自动判断：

- 正文前半段是晚上、后半段跳到了第二天早上 → 画两张：先「前半段·深夜」，再「结束时」（早上，这一楼结束时的样子）
- 从酒馆换到了森林这类换地点的情况也一样；整段都是同一个时间、同一个地方 → 只画一张，和平时一样
- 每一段的衣服、动作、场景、光线都按那一段写，模型、LoRA、分辨率和结束时那一张相同；几张图按时间顺序显示在这一楼（侧边面板里也是），每张上面写着是哪一段，点图可以放大
- 「结束时」那一张就是平时的那张图：之后楼层的连贯（衣服、状态）、「之前的配图输出」都按它算
- 🎲 换种子把这一版的几张一起重画；🔄 / 💬 重新解析，可能分成不同的几段；✏️ 只编辑、只重画「结束时」那一张；🗑 删除这一版的全部几张
- 多一张就多一次 ComfyUI 出图时间；前面某一张没画成时，🐞「处理备注」里会写原因，结束时那张照常保留
- 🐞 里能看到每一段的提示词；「试运行解析」也会列出来。两个模型模式共用这一项

## 画图指令 `[[ ]]`

在自己的消息里（发送或编辑时）用双括号写画面要求：

```
我穿上了新鞋子。[[red high-heeled shoes with ankle straps]]
我提起灯笼。【【holding a paper lantern in her left hand】】
```

- 发送时括号连同内容会从正文里拿掉，正文 AI 收到的是「我穿上了新鞋子。」，消息下方显示一行「画图指令」（点 ✕ 删除）
- 指令存在这条消息的扩展数据里，只交给配图解析模型，优先级最高，会体现在服装 / 动作等字段里；之后的楼层通过「之前的配图输出」延续
- 每条指令只在它之后的第一次配图时作为指令发送；有指令的楼层即使不在「每隔几楼」里、或者正文少于设定的 token 数，也会配图
- 保险：如果有脚本等绕过发送事件直接插入带 `[[ ]]` 的消息，发给正文 AI 的对话内容里也会去掉这些括号（只处理对话消息，不动预设/系统提示）
- 不需要时在「自动配图规则」里关闭「启用画图指令」，括号就原样保留（已经存下的指令照常生效，点 ✕ 删除）

### 对画面不满意：加画图指令重画（不改正文）

图片工具栏上的 💬（「加画图指令重画」，配图失败或被跳过时是「加指令重画」链接）：打开一个输入框，写你想要的样子，一行一条，
例如「坐在床边」「穿红色连衣裙」「和他牵着手」「近景」，点「保存并重画」。

- 指令存进这一楼（不改正文，写正文的 AI 也看不到），然后按指令**重新解析**并出图，旧图保留为一个版本
- 再点 💬 可以改或删这一楼的指令；清空就是全部删除（不重画）。消息下方的「画图指令」一行也能点 ✕ 删单条
- 和 ✏️ 的区别：✏️ 直接改最终提示词、原样发送；💬 是告诉解析 AI 要改什么，由它按当前预设重写提示词（触发词、外貌、LoRA 照常）

## 正文状态栏（让写正文的 AI 写出穿着 / 状态 / 心情）

不用世界书，也不用酒馆助手脚本，在「正文状态栏」分组里打开「让正文 AI 在每次回复末尾写状态栏」即可：

- 扩展会把一段说明自动加进发给正文 AI 的提示里（相当于作者注释，默认插在最后），要求它在每次回复的最末尾附上：

  ```
  <details><summary>状态栏</summary>

  角色：名字
  穿着：……
  动作：……
  状态：……
  心情：……
  </details>
  ```

- 酒馆会把它显示成正文下方一个**折叠的「状态栏」**，点一下展开
- 它是正文的一部分，所以**正文 AI 之后的回复也能看到**，有助于它记住人物穿着和状态
- **解析模型**会把当前楼层的状态栏单独拿出来，放在「【正文状态栏】」一节，并要求以它为准写服装、动作、表情、神态（正文用来补充细节）。🐞 调试弹窗的「处理备注」里会写「读取了正文状态栏」
- 写谁：和「画谁」一样（默认）/ {{user}} / {{char}} / 指定名字（比如某个 NPC）。「画谁」是「自动」时由 AI 自己写明是谁
- 写哪些项：默认「穿着、动作、状态、心情」，可以改，例如加上「所在位置」
- 后台的总结、酒馆助手之类的静默生成和「代入用户」不会收到这段说明
- 「预览发给正文 AI 的说明」可以看到实际发出去的文字；说明模板可以在「高级」里改

注意：

- 每楼的状态栏都留在聊天记录里，会占一些上下文（一楼大约几十到一百多 token）
- 解析模型按折叠标题（默认「状态栏」）找状态栏，改了标题后，之前楼层的状态栏就认不出了
- 如果你更想用世界书：可以不打开这个开关，把「预览」里的说明复制进一个常驻的世界书条目，只要格式一样，解析模型照样会重点参考
- 酒馆「用户设置」里的「在响应中显示标签」（Show <tags> in responses）打开时，HTML 会原样显示成文字，状态栏就不会折叠；默认是关的

## 解析模型的思考模式

「解析模型」里的 **思考模式** 和 **思考强度**：

- 默认：不发送任何思考参数（和以前一样）；关闭思考：更快、不占输出额度；开启思考：先思考再写，可以选强度 低 / 中 / 高
- 各家接口的思考参数不一样，「思考参数格式」默认按 API 地址和模型名自动判断，也可以手动选：
  - OpenAI 格式 `reasoning_effort`（OpenAI、Gemini、Grok 等；关闭 = `none`）
  - OpenRouter 格式 `reasoning: {enabled, effort}`
  - `thinking.type` 格式（智谱 GLM、豆包、DeepSeek；只有开 / 关，没有强度）
  - 通义千问格式 `enable_thinking` + `thinking_budget`（强度 低 / 中 / 高 = 1024 / 4096 / 16384 token）
  - Claude 格式 `thinking` + `budget_tokens`（同样的预算，开启时温度固定为 1）
- 设置下面会显示实际发送的参数；「附加请求参数」里自己写的同名参数优先
- 有思考预算的格式会自动把「最大输出」调到至少 预算 + 2048，留出写 JSON 的空间
- 「酒馆连接配置」：开启时把强度交给酒馆，由酒馆按服务商转换；关闭沿用连接配置自己的设置。「酒馆当前 API」：用酒馆自己的设置，这里不生效
- 思考模型偶尔把「最大输出」用完、返回空内容：把思考强度调低，或改成关闭

## 解析模型能看到什么

每次配图，解析模型收到（都可以在 🐞 调试 / 「预览解析输入」里看到完整内容）：

| 内容 | 设置 |
|---|---|
| 目标角色的固定外貌（预设） | 角色预设 |
| 世界书（可选）：当前触发的条目，或所有启用的条目 | 解析模型 → 世界书、最多字数 |
| 同一角色上一次的状态 | 状态延续 |
| **之前几次配图的输出**：每层的解析结果（服装、动作、表情、场景……）和最终提示词 | 参考之前几次配图输出（默认 3，0 = 关）、同时附上最终提示词 |
| 最近几楼剧情 + 当前楼层（已去掉画图指令） | 读取前几楼剧情、每楼最多字数、只读取正文标签里的内容 |
| 当前楼层的正文状态栏（单独一节，重点参考） | 正文状态栏 |
| 画图指令 | 启用画图指令 |

这些记录都存在消息的扩展数据（`extra`）里，不在正文中，酒馆组装正文 AI 的上下文时不会读取它们。
世界书的「当前触发的条目」用的是酒馆自己的扫描规则，但是以试运行方式扫描，不会触发事件，也不会推进正文的粘性/冷却计时。

**正文读的是什么**：默认读每楼的全文。HTML 标签本身、`<style>` 和 `<script>` 会去掉，但标签里的文字（代码页上的按钮、选项）和 ``` 代码块里的内容都会被读到。
如果正文 AI 把剧情写在 `<game>……</game>` 里，外面还有代码页、选项面板，打开「解析内容」里的**只读取正文标签里的内容**：

- 每楼只读 `<game>` 和 `</game>` 之间的内容，有好几段就全读；AI 忘了写结束标签时读到这一楼末尾
- 标签名可以改（「正文标签名」，不用写尖括号），例如 `content`、`正文`
- 没有这个标签的消息（例如你自己发的消息，或者 AI 这次没写标签）照常读全文，但去掉 ``` 代码块；🐞 调试的「处理备注」会写当前楼层有没有标签
- 剧情、可能同框的角色、世界书扫描都只用标签里的内容；正文状态栏和画面分级标记照常从全文里找
- 两个模型模式共用这一项

**隐藏角色卡的名字**（「解析内容」里）：游戏、旁白、模拟器类的卡，卡名不是一个角色，解析 AI 却会把它当成人。打开后：

- 发给解析 AI 的剧情里，AI 的消息不再标卡名，改标「正文」（世界书扫描也一样）
- 「画谁」选「自动」时，卡名不在候选里；解析 AI 写了不认识的名字时退回画 {{user}}（平时退回卡名对应的角色）
- 「可能同框的其他角色」不再带上卡名对应的角色预设
- 「画谁」选 {{char}} 时仍然用卡名；普通角色卡不要打开。两个模型模式共用

**重新解析旧楼层只往前读**：比如聊天已经到了 #30，回头给 #10 重新刷图 / 重新解析时，解析模型只能看到 #10 和它之前的内容——
剧情、之前的配图输出、上一次状态、画图指令、正文状态栏、世界书扫描、可能同框的角色，全部截止到 #10，
#11 及之后的文字、配图结果和画图指令一概不读（扩展把聊天截到 #10 之后再交给这些读取步骤）。
🐞 调试弹窗的「处理备注」里会写「只读取 #10 及之前的楼层，之后的 20 楼不读取」。

## 套装（服装参考）

角色预设里的 **套装**：一行一套，写成 `名称：提示词`，例如

```
校服：white short-sleeved sailor blouse, red neckerchief, navy pleated skirt, black knee socks
睡衣：oversized pale pink pajama shirt and shorts, barefoot
```

画这个角色时，套装列表会发给写画图提示词的解析 AI 作参考：剧情里写到她穿上其中某一套（或者画图指令里写 `[[换上校服]]`），
服装（outfit）就照这套的提示词写，再按剧情补充穿着状态（比如外套敞开、袖子卷起）；剧情没写到换装就不会换。
套装不会直接放进提示词，只是参考。提示词按当前模式写：Krea 2 写英文描述，Anima 写标签（或开了「英文自然语言」时写英文描述）。
「自动判断」画谁时，每个候选角色的套装都会附上。

## {{user}} 用哪个角色预设

画 {{user}} 时，用名字或别名和当前人设名相同的预设（名字写 `{{user}}` 的预设总能对上）；没有就用「角色预设」最上面「{{user}} 没有同名预设时使用」选的预设；
选了「不使用角色预设」就不加固定外貌，模型和风格 LoRA 用「出图参数」里的默认值。

不同的用户人设要用不同的外貌、LoRA、提示词：打开最上面的「每个用户人设使用独立档案」（默认打开），每个人设有自己的一整套设置，切换人设时自动换过去（见「每个用户人设一个档案」）。

## 渲染配置（不同角色用不同的模型 / LoRA）

「出图参数」里的扩散模型、文本编码器、VAE、风格 LoRA、步数、CFG、采样器、调度器是**默认值**。
想让某个角色（或某个用户人设）用别的模型或 LoRA：

1. 在「出图参数」分组下面的「渲染配置」里点 + 新建，起个名字，只填要改的项：
   - 模型类下拉框的第一项「（默认：xxx）」= 沿用默认值；风格 LoRA 还可以选「（不使用）」，去掉默认的风格 LoRA
   - 风格 LoRA 的强度只在这里选了 LoRA 时生效
   - 步数、CFG 填 0 = 沿用默认值
   - 「专用工作流」可选：换成另一类模型（需要不同的节点）时粘贴它的 API 格式工作流，留空就用「工作流」里选的工作流
2. 在「角色预设」里给角色选「渲染配置」
3. 画这个角色时就用配置里的设置，没填的项用默认值

例：NPC「莉娜」的预设选渲染配置「动漫」（动漫模型、不用风格 LoRA、20 步），其他角色用默认的写实模型；画到莉娜时就换成动漫模型。

- 角色 LoRA（「出图参数 → LoRA」里给角色设置的）和风格 LoRA（默认或渲染配置里的）同时使用，互不影响
- 分辨率仍由「出图参数」或配图风格决定，不在渲染配置里
- 🐞 调试弹窗的「③ ComfyUI 参数」里能看到这张图用的是哪个渲染配置
- 删除渲染配置时，用它的角色预设会改回默认设置
- 导出角色预设时会带上渲染配置，导入时一起导入

## 分辨率：固定宽高 / 分辨率选择器

「出图参数 → 分辨率」里选分辨率方式：

- **固定宽高**：直接填宽和高（下拉里有常用尺寸），和以前一样
- **分辨率选择器**：选宽高比（1:1、2:3、3:4、9:16、3:2、4:3、16:9、21:9）和像素数（MP），宽高自动算出来并对齐到 16 的倍数，
  和 ComfyUI 的 Resolution Selector 节点一样（例：2:3、1 MP → 832×1248；16:9、1 MP → 1360×768）
- 选择器下面的「让解析模型按画面选择宽高比」：解析模型在同一次请求里多写一个 aspect 字段，只能从上面这些比例里选，按构图挑——
  全身、站姿用竖图，特写用方图或 3:4，横向展开的场景、几个人并排用横图。**只调整宽高比，像素数不变**；拿不准时用你选的宽高比
- 优先级：✏️ 编辑窗口填的尺寸 > 配图风格（解析预设）自己设的分辨率 > 分辨率选择器 / 固定宽高
- 🐞 调试里的「宽高比」一行会写明是不是解析模型选的；每个模式、每个人设档案各自保存

### 检查发给解析 AI 的内容

画错了想知道解析 AI 读到了什么，有三种办法：

- **预览解析输入**（设置面板最上面，「调试与维护」里也有）：看最新一楼会发给解析模型的完整内容，不发送请求
- **发送前检查解析输入**（最上面「调试模式」旁边的勾选）：打开后，每次请求解析模型之前（自动配图、🔄、🖼、💬 都算）先弹出这次要发送的全部内容：
  - 上面一行是目标角色、解析预设和处理说明（读了哪几楼、有没有找到 `<game>` 标签、世界书、画图指令……）
  - **System**：规则（解析预设的提示词 + 输出规则）；**User**：剧情和参考资料，其中【当前楼层】一节就是这一楼读到的正文
  - 两段都可以直接改，只对这一次生效（🐞 里会记下「解析输入在发送前被手动修改过」）；点「发送」继续解析出图，点「取消」这一楼这次不配图
  - 两个模型模式共用；检查完记得关掉，不然每次配图都会弹出
- **调试模式**：每张图的 🐞 里能看到当时实际发送的 System / User 和解析模型的原始输出

「调试与维护」里的 **全部恢复默认值**：把扩展的所有设置恢复成刚安装时的样子。默认保留角色预设、渲染配置、自己建的配图风格，
以及解析模型 / ComfyUI 的连接信息（地址、Key、模型列表），每一项都可以取消勾选；聊天里已经生成的图片不受影响。

> 解析模型的完整输入和工作流只在调试模式开启时记录（避免聊天文件变大）；最终提示词、解析结果和出图参数始终记录。

/ctimg-target auto           切换目标：预设名 / user / char / auto
/ctimg-preset 立绘           切换配图风格（解析预设，可以只写名字的一部分）

## 提示词是怎么拼的

解析模型返回 JSON：

```json
{"skip": false, "target": "...", "outfit": "...", "action": "...", "expression": "...",
 "demeanor": "...", "scene": "...", "camera": "...", "lighting": "..."}
```

然后套进「组装模板」（可在设置里改）：

```
{{trigger}} {{prefix}}
A solo image of a single person, only one person in the frame.
{{appearance}}
Wearing {{outfit}}.
{{action}}.
Facial expression: {{expression}}. {{demeanor}}.
Setting: {{scene}}.
{{camera}}, {{lighting}}.
{{suffix}}
```

某一行的变量全为空时整行省略。`{{appearance}}` 来自角色预设，`{{trigger}}` 是本模式的触发词加上角色预设的 LoRA 触发词，`{{prefix}}` / `{{suffix}}` 是全局画风设置，其余来自解析模型。
不管模板怎么写，本模式的触发词都会出现在最终提示词里（模板里没有就补在最前面）。

Anima 模式的默认模板按标签写，每行之间用**逗号**连接（Krea 2 是每行一句话、用句号连接）：

```
{{trigger}}, {{prefix}}
solo
{{appearance}}
{{outfit}}
{{action}}
{{expression}}, {{demeanor}}
{{scene}}
{{camera}}, {{lighting}}
{{suffix}}
```

例：`my_style, masterpiece, best quality, score_7, solo, 1girl, long hair, black hair, amber eyes, grey hoodie, black leggings, sitting, holding cup, light smile, forest, dusk, cowboy shot, backlighting`。
画面里有其他人时去掉 `solo`，`{{others}}`（也是标签，例如 `1boy, short hair, on left`）加在镜头那一行前面。
配图风格允许其他人物、而且这张图里真的有其他人时，「A solo image…」这一行会被去掉，`{{others}}` 加在镜头那一行前面（模板里自己写了 `{{others}}` 就用你写的位置）。

开启「状态延续」时，解析模型会拿到同一角色上一张图的服装、场景等，剧情里没换装就保持一致。

## 使用自己的工作流

工作流选「自定义」，粘贴 ComfyUI **导出(API)** 得到的 JSON。可用占位符（整个字符串等于占位符时会替换成对应类型的值）：

```
%prompt% %negative_prompt% %width% %height% %seed% %steps% %cfg% %sampler% %scheduler%
%unet% %clip% %vae% %lora% %lora_strength% %char_lora% %char_lora_strength% %filename_prefix%
```

- `lora_name` 为空的 LoRA 节点会被自动旁路（上下游自动连上），所以没有 LoRA 时不用改工作流
- 如果工作流里没有 `%prompt%`，会自动顺着 KSampler 的 positive / negative 找到文本编码节点写入提示词，并写入种子和分辨率
- 「校验」按钮会检查格式、列出占位符和处理备注；UI 格式的工作流会被拒绝并提示改用 API 格式导出

## 正文 AI 为什么看不到

- 图片、提示词、解析结果都存在 `message.extra.comfy_portrait`（以及对应 swipe 的 `swipe_info[i].extra`）里，酒馆组装上下文时不会读取这个字段
- 不使用酒馆自带的 `extra.image` / `extra.media`，所以即使开了「发送图片」也不会把配图发给多模态模型
- 图片由扩展自己插入到消息 DOM 中，`mes` 正文一个字都不改
- 解析模型的请求是独立请求，不进聊天记录

## 常见问题

- **同一段提示词，放进 ComfyUI 官方 Krea 2 Turbo 模板出的图和这里不一样**：主要原因是官方模板默认开着「Refine Prompt（提示词扩写）」——
  它先让文本编码器（Qwen3-VL）按模板自带的一段说明把你的提示词扩写成一段更长的描述，再用扩写后的文字出图；扩展的内置工作流默认不扩写。
  其余部分（UNETLoader、CLIPLoader `krea2`、EmptyLatentImage、KSampler 8 步 / CFG 1 / euler / simple、空负向）和官方模板一致。
  想要一样的效果：
  - 「工作流」里勾选「ComfyUI 端提示词扩写」：内置工作流加上和官方模板相同的扩写步骤（同样的说明、max_length 512、temperature 0.7 等参数）。需要较新的 ComfyUI（有 TextGenerate 节点），每张图多花几秒；「浏览器直连」模式下，🐞 调试弹窗会显示「ComfyUI 扩写后的提示词」
  - 「出图参数」里的「恢复为官方 Krea 2 Turbo 模板的设置」：一键把工作流、模型、风格 LoRA、分辨率（1024×1024）、采样（8 步、CFG 1、euler / simple）恢复成官方默认值，提示词扩写保持关闭；ComfyUI 地址、连接方式、渲染配置、角色预设不变
  - 用 ✏️ 编辑提示词后生成时，可以直接填种子、尺寸，并取消角色 LoRA、风格 LoRA、渲染配置（见「每楼的操作」）
  - 另外几处也会让图不同：种子（默认每次随机，🐞「③ ComfyUI 参数」里能看到这张图的种子，填进 ComfyUI 才能复现同一张）、角色预设的角色 LoRA 和触发词、风格 LoRA、渲染配置换掉的模型、分辨率。官方模板开 LoRA 时把触发词加在提示词末尾，扩展加在最前面

- **代理模式报错只有一句 “ComfyUI returned an error.”**：这是酒馆后端代理的限制。临时切到「浏览器直连」（ComfyUI 用 `--enable-cors-header` 启动）可以看到具体是哪个节点、什么错误
- **「从 ComfyUI 读取列表」只读到部分列表**：酒馆后端只提供扩散模型、VAE、采样器、调度器的列表，没有 LoRA 和文本编码器的接口；
  这两个列表要由浏览器直接访问 ComfyUI 的 `/object_info` 读取。做法：ComfyUI 加启动参数 `--listen --enable-cors-header`，
  在「浏览器直连地址」填浏览器所在设备能访问到的地址（用手机访问酒馆时填电脑的局域网 IP，如 `http://192.168.1.10:8188`，
  手机上的 `127.0.0.1` 指的是手机自己）。读不到也可以在下拉框里选「手动输入」。读到的列表会缓存，下次不用重新读
- **偶尔报「配图失败（解析模型）」，比如 `API request failed ← Invalid API parameter, please check the documentation.`，多点几次又好了**：
  这是解析模型的接口偶尔拒绝了请求（同样的请求下次又能通过），不是 ComfyUI 的问题。现在会自动重试：
  「解析模型」里的「失败自动重试次数」默认 2 次，接口报错（包括 429、502 这类）或者没返回可用的 JSON 时，等一两秒再请求，
  重试时配图条显示「解析失败，正在重试（1/2）…」，🐞 调试弹窗的「处理备注」里记录每次失败的原因。
  取消、超时、设置填错、输出被截断不会重试。重试次数用完还失败，错误会写成「解析模型连续 3 次失败 ← 原因」
- **解析失败「返回了空内容」/「输出被截断」**：多半是思考模型把「最大输出」用在思考上了。调大「最大输出」（默认 2048），
  或在「附加请求参数」里关闭思考。🐞 调试弹窗里能看到结束原因（finish_reason）和思考内容
- **Anima 模式和 Krea 2 模式能不能共用角色预设**：两边是分开的。想把 Krea 2 的角色搬过去：在 Krea 2 模式「角色预设」里导出，切到 Anima 后导入，
  再把外貌改成标签写法（如 `1girl, long hair, black hair, amber eyes`），角色 LoRA 换成 Anima 的 LoRA
- **同样的 LoRA 和强度，Anima 出图和 ComfyUI 里不一样**：多半是 LoRA 节点不同。ComfyUI 里常用的「加载 LoRA」会同时改模型和文本编码器，v1.15 之前内置 Anima 工作流只改模型。现在默认和「加载 LoRA」一样；如果你在 ComfyUI 里用的是「仅模型」的节点，关掉「出图参数 → LoRA 同时作用于文本编码器」。另外检查触发词、画风前缀、括号转义和种子（🐞 里能看到实际发送的提示词和 LoRA）
- **Anima 出图和官方 Anima 模板不一样**：内置工作流和官方模板相同（30 步、CFG 4、euler / simple、同样的反向提示词；扩展默认还会让解析模型补充几个反向标签，对比时在 ✏️ 里把反向提示词改成一样的，或在「提示词组装」里关掉补充），差别通常在提示词、种子、尺寸和 LoRA。
  用 ✏️ 编辑后生成可以填同样的提示词、种子和尺寸、去掉 LoRA，和官方模板对比；官方模板打开 turbo_mode 时对应「改用官方 Turbo LoRA」
- **Anima 的提示词写法**：Anima 用 Danbooru 标签和自然语言描述训练，两种都能用。常见写法是 画质 / 评分标签 → 人数标签（1girl）→ 角色 → 作品 → 画师（`@画师名`）→ 其他标签。
  这些规则（尤其是 `@画师名` 的写法）来自 Anima 的模型说明，扩展没有在实际模型上逐条验证过，效果以你自己的测试为准
- **分辨率**：Krea 2 Turbo 适合约 1–2 MP，最高约 4 MP；Anima 按约 1 MP 训练。设置里会显示当前像素数，超出推荐范围（Krea 2 超过 4 MP，Anima 超过约 1.6 MP）会提示——过大容易画出重复的人物或多余肢体
- **解析模型偶尔输出跳过**：剧情里目标角色不在场时会跳过；调试模式下能看到跳过原因并「强制生成」。手动触发（按钮、斜杠命令）总是强制生成
- **API Key 存在哪**：存在酒馆的扩展设置（`settings.json`）里，请求时作为请求头经酒馆后端转发
